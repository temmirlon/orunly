# orunly — Техническое задание

> «орун» (кырг.) — «место».
> Версия: 0.1 (черновик) · Дата: 2026-11-01 · Статус: на согласовании

---

## 1. Общие сведения

**orunly** — веб-платформа для анализа локаций и недвижимости с ИИ-консультантом («ИИ-риелтор»).
Пользователь вводит район, адрес или область на карте и получает: цены, инфраструктуру,
транспорт, образование, экологию, а также плюсы, минусы и компромиссы этого места
в соответствии с его собственными приоритетами.

Первый целевой город — **Мюнхен**. Архитектура изначально рассчитана на другие города и страны.

### 1.1 Цели
1. Ответить на вопросы: *«Где сколько стоит? Сколько за м²? Какой размер участка? Что вокруг?»*
2. Дать **честный, прозрачный** анализ: у каждой цифры есть источник, дата и степень достоверности.
3. Позволить каждому задать свои приоритеты (кому-то важен район, кому-то площадь, участок, цена, престиж)
   и получить персональную оценку.
4. Сделать ИИ-консультанта, который объясняет компромиссы на основе **реальных данных платформы**, а не выдумывает числа.
5. Сделать проект портфолио-уровня (публичный GitHub): чистая архитектура, документация, тесты, CI.

### 1.2 Не-цели (на старте)
- Парсинг порталов, запрещающих его в своих условиях (ImmoScout24 и др.). См. раздел 5.
- Размещение или посредничество по объявлениям, платежи, мобильные приложения.
- Юридические, налоговые и финансовые консультации (только справочная информация с дисклеймером).
- Мультитенантность и пользовательские аккаунты в MVP.

### 1.3 Аудитория
- **Сейчас:** личный инструмент автора.
- **Далее:** публичная демо-версия для портфолио. Архитектура должна допускать аккаунты и GDPR, но в MVP их нет.

## 2. Принципы архитектуры

Главное требование: **расширять систему без большого рефакторинга**. Ключевые оси расширения:

| Ось | Что должно быть возможно без изменения ядра |
|---|---|
| Город / страна | Добавить новый город через конфигурацию и адаптеры данных («Country/City Pack») |
| Источник данных | Подключить новый источник как плагин-адаптер |
| Метрика | Добавить новую метрику как плагин с описанием (единица, категория, направление «больше = лучше») |
| LLM | Заменить Gemini на другую модель или локальную (Ollama) сменой конфигурации |
| Тип анализа | Позже анализировать не только жильё (бизнес-локации и т.п.) |

Правила:
- **Модульный монолит**, а не микросервисы. Границы модулей строгие, деплой один. Это проще и достаточно для проекта.
- **YAGNI для «других доменов»:** в MVP не строим универсальный движок. Достаточно не зашивать «жильё» в ядро
  (метрики и регионы доменно-нейтральны), а сам домен живёт в слое конфигурации и метрик.
- **Зависимости направлены внутрь:** `api → services → domain ← adapters` (порты и адаптеры / hexagonal).
- Все внешние системы (источники данных, LLM, геокодер, роутинг) скрыты за интерфейсами (`Protocol`/ABC).
- Страна-специфичное (валюта, единицы, термины вроде Kaltmiete/Warmmiete, набор метрик) только в Country Pack.

| **Среда** | Доля зелени, парки, шум, качество воздуха | P1 |
| **Безопасность** | Статистика преступности, если есть на уровне района | P2 |

### 3.3 ИИ-консультант
| ID | Требование | Приоритет |
|---|---|---|
| F-20 | Чат на естественном языке (RU/EN/DE) поверх данных платформы | P0 |

### 3.4 Интерфейс
- Веб-сайт (desktop-first, адаптивный).
- **Языки: английский и немецкий** (требование организации). Русский добавляется позже как P2. Весь текст проходит через i18n,
  без склейки строк, с локале-зависимым форматированием чисел, дат и валют.
- **Светлая и тёмная тема** обязательны. Шрифт **Open Sans** (корпоративный дизайн SF).

## 4. Архитектура

### 4.1 Компоненты

```
┌────────────┐   REST/SSE   ┌─────────────────────────────────────────────┐
│  Frontend  │ ───────────▶ │  Backend (FastAPI, modular monolith)        │
│  Next.js   │              │  ┌─────────┐ ┌──────────┐ ┌──────────────┐  │
│  MapLibre  │              │  │ API v1  │▶│ Services │▶│ Domain core  │  │
└────────────┘              │  └─────────┘ └────┬─────┘ │ Region,Metric│  │
                            │                   │       │ Scoring      │  │
                            │        ┌──────────┴────┐  └──────▲───────┘  │
                            │        │  AI layer     │         │          │
                            │        │  LLMProvider  │   ┌─────┴───────┐  │
                            │        │  tools, cache │   │  Adapters   │  │
                            │        └──────┬────────┘   │  (ports)    │  │
                            └───────────────┼────────────┴──┬──────────┬──┘
                                            │               │          │
                                  Gemini / Ollama     PostgreSQL   Data sources
                                                      + PostGIS    (OSM, GTFS, ...)
                                                                   ▲
                                                      Ingestion pipeline (CLI/scheduler)
```

### 4.2 Модули backend
| Модуль | Ответственность |
|---|---|
| `domain` | Сущности `Region`, `Metric`, `MetricValue`, `Source`, `ScoreProfile`. Чистая логика без внешних зависимостей |
| `ingestion` | Адаптеры источников (`DataSource` протокол), нормализация, загрузка, расписание, идемпотентность, журнал запусков |
| `metrics` | Реестр метрик (плагины): как считать метрику для региона/геометрии |
| `scoring` | Нормализация метрик, взвешивание по профилю, объяснение скора |
| `geo` | Геокодирование, пространственные запросы, иерархия регионов |
| `ai` | `LLMProvider` (Gemini, Ollama, ...), описания tools, ограничение частоты, кэш, защита от «выдумок» |
| `api` | HTTP API `/api/v1`, схемы (Pydantic), ошибки с кодами для i18n |
| `packs` | Country/City Pack: конфиг города, список источников и метрик, локаль, валюта |
| `core` | Конфигурация, константы, логирование, обработка ошибок |

### 4.3 Модель данных (черновик)
- `source(id, name, url, license, attribution, terms_status)`
- `region(id, country_code, level, parent_id, name_i18n, geometry, external_ids)`
- `metric_def(key, category, unit, higher_is_better, description_i18n)`
- `metric_value(region_id, metric_key, value, period, source_id, fetched_at, confidence)`
- `score_profile(id, name, weights)`
- `ingestion_run(id, source_id, started_at, finished_at, status, stats)`

SQL только через параметризованные запросы / ORM (SQLAlchemy 2.x), миграции через Alembic.

### 4.4 Технологический стек
| Слой | Выбор | Обоснование |
|---|---|---|
| Backend | Python + FastAPI | Лучшая экосистема для данных, геоданных и ИИ |
| Окружение Python | `uv` + `.venv` | Виртуальное окружение обязательно, зависимости только внутри него |
| БД | PostgreSQL + PostGIS | Геозапросы, полигоны, индексы |
| Миграции | Alembic | Стандарт для SQLAlchemy |
| Frontend | Next.js + TypeScript | SSR, роутинг, i18n |
| Карта | MapLibre GL | Открытый стек, без привязки к платному провайдеру |
| i18n | `next-intl` (frontend), коды ошибок/ключи (backend) | EN/DE из коробки |
| Инфраструктура | Docker Compose, GitHub Actions | Запуск одной командой, CI |
| Тесты | pytest, (позже) Playwright | |

Версии: для всех зависимостей берётся **последняя стабильная** на момент установки. Откат на старую версию только
с задокументированной причиной.

## 5. Источники данных

### 5.1 Позиция по парсингу
- **ImmoScout24 не парсим.** Их условия запрещают краулеры и роботов, а официальный API требует договора и не предназначен
  для сбора рыночных данных ([условия API](https://api.immobilienscout24.de/terms-of-use/en/)).
- Подход: **анализ регионов на открытых и лицензируемых данных**. Объявления не обязательны.
- Каждый источник проходит **проверку лицензии и условий** до подключения. Статус хранится в `source.terms_status`
  и в реестре ниже. Для сайтов без явного разрешения парсер не пишем.

### 5.2 Реестр источников (Munich)
| Источник | Данные | Лицензия / статус |
|---|---|---|
| OpenStreetMap (Overpass / выгрузки Geofabrik) | Школы, магазины, парки, остановки, границы | ODbL, нужна атрибуция. Подходит |
| MVV GTFS (opendata-oepnv.de) | Расписания и остановки транспорта | CC-BY, нужна атрибуция MVV и дата получения. Покрытие нужно перепроверить ([OSM Wiki](https://wiki.openstreetmap.org/wiki/M%C3%BCnchen/Transportation/MVV-GTFS)) |
| [open-property-location](https://github.com/ls-itsolutions/open-property-location) | Готовые окружение/расстояния по адресу (на базе OSM) | Использовать как референс или зависимость, лицензию проверить |
| Münchner Mietspiegel | Ориентир аренды по кварталам | **Проверить**: доступность в машиночитаемом виде и условия |
| Bodenrichtwerte (BORIS Bayern) | Стоимость земли €/м² | **Проверить**: API, лицензия |
| Zensus 2022 / Destatis | Демография, жильё, плотность | **Проверить** лицензию и формат |
| Open Data Portal Stadt München | Городские наборы данных (границы, зелень и т.д.) | **Проверить** набор за набором |
| ALKIS / кадастр Баварии | Размеры участков | **Проверить**: открыт ли и в каком виде |
| Шум, воздух, статистика преступности | Среда и безопасность | **Проверить** наличие на уровне района |

> Реальность данных: открытые источники дают в основном **агрегаты** (по кварталам и периодам) с задержкой,
> а не текущие цены объявлений. Это нужно честно показывать в UI (дата и «тип данных: оценка/статистика»).
> Если цены объявлений понадобятся, то только через легальный путь (официальный API, договор, платный провайдер) как отдельный адаптер.

### 5.3 Требования к ingestion
- Адаптер = класс, реализующий протокол `DataSource` (`fetch → normalize → load`).
- Идемпотентность, повторный запуск без дублей, журнал запусков.
- Уважение `robots.txt`, условий использования, rate limit и кэширование (если источник это допускает).
- Хранение только разрешённого. **Скачанные данные не коммитятся в репозиторий**, коммитятся скрипты и документация.
- Атрибуция источников видна в UI (страница «Источники и лицензии»).

## 6. ИИ-слой

### 6.1 Факты о Gemini API (проверено)
- Подписка **Google AI Pro сама по себе не даёт API-ключа и бесплатных вызовов API**. Она повышает лимиты в AI Studio и Gemini CLI,
  но не лимиты API-ключа ([Google AI plans](https://ai.google.dev/gemini-api/docs/google-ai-plans)).
- **Но** подписчики Pro получают **$10/мес в Google Cloud credits** (Ultra — $100), которые можно потратить на Gemini API
  через AI Studio или Vertex AI ([анонс Google](https://blog.google/innovation-and-ai/technology/developers-tools/gdp-premium-ai-pro-ultra/)).
  Условия:
  - кредиты нужно активировать в Google Developer Program (developers.google.com/program/my-benefits);
  - нужен проект GCP с включённым Cloud Billing (то есть привязанная платёжная карта);
  - кредиты ложатся на счёт Cloud Billing и вычитаются из ежемесячного счёта, баланса «$10» в AI Studio не видно;
  - по сторонним источникам, срок действия каждой выдачи 12 месяцев; на prepaid-счёте кредиты могут не работать,
    безопаснее postpaid-аккаунт. Это **требует проверки** при настройке.
  - Официальная страница AI plans не фиксирует сумму ("if any"), поэтому актуальность суммы перепроверять.
- Бесплатный API-ключ из Google AI Studio работает без карты, но с 1 апреля 2026 доступен только для моделей Flash/Flash-Lite,
  с жёсткими лимитами (порядка 10 запросов/мин, ~1000–1500/день; точные числа смотреть в консоли AI Studio).
- На бесплатном уровне Google может использовать запросы и ответы для улучшения продуктов, на платном — нет.
  В любом случае **персональные данные в запросы не отправляем**.
- Не использовать обходные неофициальные способы «прокинуть» подписку в API (риск нарушения условий).
- **Защита от перерасхода:** при подключённом Billing обязательны бюджет с алертами (Cloud Billing budgets), квоты на проект
  и лимит запросов на стороне приложения (AI-05), чтобы сверх $10 не списывалось с карты.

**Варианты для MVP** (выбирается конфигурацией благодаря `LLMProvider`):
1. Бесплатный ключ, только Flash. Без карты, но малые лимиты и данные могут идти на обучение.
2. Ключ на проекте с Billing + $10 кредитов. Выше лимиты, данные не идут на обучение, но нужна карта и контроль расходов.
3. Локальная модель (Ollama). Бесплатно, но слабее и нужен мощный компьютер.

### 6.2 Требования
| ID | Требование |
|---|---|
| AI-01 | Интерфейс `LLMProvider` (chat, tool calling, streaming). Реализации: `GeminiProvider` (MVP), `OllamaProvider` (локально, P1) |
| AI-02 | Имя модели, ключи и лимиты только в конфигурации, не в коде |

| AI-08 | Логирование вызовов LLM (модель, длительность, токены, ошибки) без персональных данных |

## 7. Нефункциональные требования

### 7.1 Логирование и ошибки
- Логи **в консоль и в файл** (ротация), уровни `DEBUG/INFO/WARNING/ERROR/CRITICAL`, структурированный формат (JSON в файл).
- `DEBUG` достаточно подробен, чтобы проследить работу рантайма: запуски ingestion, запросы к источникам, выбор метрик, вызовы LLM.
- Типизированные исключения домена, единый формат ошибок API (`code`, `message_key`, `details`), без утечки внутренностей.
- Корреляционный ID запроса сквозь логи.

### 7.2 Код и конфигурация
- **Никаких «магических» значений:** числа, строки, URL, пути и лимиты вынесены в именованные константы
  (`core/constants.py` и конфигурация по окружению).
- Конфигурация через переменные окружения, пример в `.env.example`. **Секреты не коммитятся** (репозиторий публичный).
- Типизация (mypy/pyright), линтер/форматтер (ruff), pre-commit.
- Коммиты по спецификации [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)
  (`feat(ingestion): add MVV GTFS adapter`, `fix(api): ...`, `docs: ...`). Проверка формата в pre-commit/CI (например, commitlint).

### 7.3 Безопасность и приватность
- SQL только параметризованный. Валидация входа (Pydantic). Rate limiting API, CORS по списку.
- GDPR-ready: в MVP не хранятся персональные данные. При появлении аккаунтов нужны политика, удаление данных, Impressum.

### 7.4 Производительность и надёжность
- Целевые показатели MVP: карточка региона из кэша/БД p95 < 500 мс, поиск p95 < 300 мс (на данных одного города).
- Ingestion не блокирует API. Сбой одного источника не ломает остальные.

### 7.5 Качество (портфолио)
- Тесты: unit для domain/scoring, интеграционные для адаптеров (с записанными фикстурами) и API. CI на GitHub Actions.
- Документация: README, диаграмма архитектуры, ADR (журнал решений), инструкция «поднять за 5 минут» (`docker compose up`).
- Страница «Источники и лицензии» с обязательной атрибуцией (OSM, MVV и др.).

### Критерии приёмки MVP
1. По любому кварталу Мюнхена показываются метрики с источником и датой.
2. Сравнение 2–4 районов с персональным скором по весам пользователя.
3. Чат отвечает на вопрос вида «где в Мюнхене удобно жить студенту TUM» и опирается на данные платформы с указанием источников.
4. UI на EN и DE, светлая и тёмная тема.
5. Проект поднимается командой `docker compose up`, тесты проходят в CI.
6. **Тест расширяемости:** добавление нового источника или метрики не требует правок в `domain` и `api`.

## 9. Риски

| Риск | Митигация |
|---|---|
| Открытых данных по ценам мало или они грубые | Показывать честную гранулярность. План B: легальные платные провайдеры, ручные выгрузки отчётов Gutachterausschuss |
| Лимиты бесплатного Gemini | Кэш, очередь, абстракция провайдера, Ollama как запасной вариант |
| Нарушение лицензий источников | Реестр лицензий, проверка до подключения, атрибуция |
| Переусложнение «универсальной» архитектуры | YAGNI: абстракции только по реально нужным осям (раздел 2) |
| Галлюцинации ИИ в числах | Tool calling, числа только из результатов tools, ссылки на источники |
| Изменение условий Gemini/источников | Всё сменно через конфигурацию и адаптеры |
